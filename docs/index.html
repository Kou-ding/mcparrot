Introduction

What is MCParrot and why does it exist?

What is Penetration Testing?

Penetration testing (or pentesting) is the practice of simulating cyber-attacks against information systems to discover exploitable vulnerabilities. Security professionals follow five distinct stages:

  • Reconnaissance Gathering target information
  • Scanning Identifying the attack surface
  • Vulnerability Assessment Identifying potential flaws
  • Exploitation Testing if vulnerabilities can be exploited
  • Reporting Compiling findings for the client

The Problem

Can a large language model actually carry a penetration test? Alone, no. An LLM is a brain in a jar.

Pentesting demands

  • Significant time investment
  • Specialized knowledge
  • Years of experience

LLMs lack

  • Tools to act
  • Domain knowledge
  • Guidance

MCParrot equips LLMs with:

  • Multiple MCP servers to act
  • An FSM to plan
  • System Prompts to specialize
  • Structured memory to retain important information
  • Two modes to achieve operational granularity

MCParrot aims to assist pentesting researchers and automate the pentesting process end-to-end.

Core Features

What makes MCParrot a powerful pentesting companion

Hawk Mode

Targeted & Direct

Hawk mode is a user-driven, open-ended execution mode. It accepts a user prompt and performs targeted pentesting operations based on user requirements. Best for specific questions, CTF challenges, and focused exploitation attempts.

  • Direct user prompt input
  • MCP servers for tool execution
  • Custom system prompt with role-playing
  • Python venv for package installation
  • No root privileges (simulated attacker constraints)

Raven Mode

Methodical & Autonomous

Raven mode is a fully autonomous, multi-agent orchestration mode. Provide just an IP address and it methodically executes the entire pentest lifecycle: Recon → Vulnerability Assessment → Exploitation.

  • Only requires a target IP
  • Multiple specialized agents (Planner, Executor, Curtain Caller)
  • Adaptive system prompts per agent
  • Automatic context switching
  • Dynamic MCP server selection per stage

FSM Architecture

Structured penetration testing workflow through Recon, Vulnerability Assessment, and Exploitation stages.

Blackboard Memory

Memory split across message history, stage plans, and summaries to prevent context window saturation.

Native Reasoning

Leverages "thinking" LLMs with native reasoning, surpassing traditional Chain-of-Thought prompting.

Jailbreaking

Carefully engineered prompts that bypass standard LLM safety filters for cybersecurity use cases.

MCP Servers

Custom Model Context Protocol servers for secure, standardized tool integration.

Realistic Evaluation

Tested against real CTF challenges and vulnerable VMs.

Architecture

How the framework is designed

Hawk Mode Loop

The Hawk loop is a direct interaction cycle. The LLM communicates with MCP servers, maintains memory via message history and follows a carefully crafted system prompt.

Raven Mode Loop

Raven operates in three colored stages:

  • Reconnaissance,
  • Vulnerability Assessment and
  • Exploitation.

Each stage follows: Plan Generation → Plan Execution & Update → Plan Summary. The cycle can repeat, building on existing plans and summaries.

MCP Protocol Flow

In both modes, the execution loop terminates only when the LLM yields a text-only response, devoid of any further tool calls. This forms a continuous loop allowing for a surprising amount of automation, even in Hawk mode, since the agent can keep probing, exploiting, and adapting via MCP servers until it achieves its goal.

Blackboard Memory Management

Unlike Hawk mode, where all information lives in message history, Raven mode distributes memory across three locations to prevent context window saturation:

Message History

Recent conversation turns between the user and agents.

Stage Plans

Structured plans for each pentesting stage with step-by-step instructions.

Summary

Condensed findings from previous cycles, enabling iterative improvement.
